# Spirits Calling — 重新設計技術設計文件（Redesign v2）

> 建立：2026-07-24 ｜ 由 2026-07-23/24 深夜設計會談收斂而成
> 前身：`.kiro/specs/spirits-calling-requirements/`（舊「兩隊互K RTS」設計，已被本文件取代為 game-design 層；其建置的 runtime/packaging/Nakama 基礎設施在本設計中**保留並重用**）

## 0. 為什麼要重新設計（誠實根因）

專案負責人於 2026-07-24 親自試玩打包後的 Shipping 版，結論是「**很無聊**」。逐項根因：

- **沒有弧線**：一開場就把召喚 1/2/3 與附身全給你，沒有「從弱變強」的過程。
- **附身無回報**：附身後只是同一單位 +35%、一樣只有輕/重擊；AI 未附身單位也在自動互K。整個賣點「靈魂附身」等於是假的。
- **沒有決策也沒有爽感**：召喚無腦、戰鬥壓著打、沒有張力曲線、沒有引導。

本設計不是修 bug，是**核心玩法 pivot**。工程地基（能編譯、能打包、測試全綠）在前一輪已完成且保留；本文件重寫的是「地基之上的遊戲」。

## 1. 核心概念一句話

> **一縷弱小的靈魂，在一片逐漸被「虛無」吞噬的靈界戰場上潛行求生：靠探索累積「心靈」以解鎖附身不同階級的「義體」，在成長（脆弱的魂體）與保命（強大但消耗的義體）之間反覆賭命，最終在完全擴張的危險地帶裡靠附身翻盤。**

市面上沒有「弱靈魂潛行探索、攢心靈解鎖附身階級、反向縮圈求生」的 roguelite——這是零預算獨立遊戲唯一能贏的戰場：拼**沒人有的機制**，不是拼美術/手感（現階段都缺）。

## 2. 五根設計柱（本設計的骨架，互相咬合）

### 柱 1 — 節奏脊椎：反向縮圈（空間化計時器）

一場 run 的天然節奏，用**空間**而非數字製造強制難度曲線：

```
安全地帶（暖身/環境式教學）
  → 危險地帶出現（會消滅魂體的機制，壓力上升）
    → 危險地帶擴張（掙扎變強）
      → 終局：危險地帶吞沒全圖（魂體裸奔會被消滅，附身成生存剛需）
死亡/一場結束 → 帶著本場學到的開下一場（危險來得更快/更兇 = 難度階）
```

- 這是大逃殺「毒圈」的引擎，但用「危險區**擴張**」而非「安全區縮小」——體感更好：玩家看著黑暗從邊緣吞噬地圖，是可讀、有畫面的恐懼，比倒數數字強。
- 前期悠閒（安全區大）、後期窒息（危險區吞全圖），過渡是一片黑暗在逼近，不是一個數字在跳。

### 柱 2 — 核心動詞：魂體 ⇄ 義體 的推幣式抉擇

```
魂體階段（成長 / 風險）        義體階段（保命 / 威能 / 消耗）
──────────────────         ──────────────────────
- 出去探索、吸心靈、變強         - 跳進事先備好的軀殼
- 脆弱：被敵靈/敵單位發現         - 安全 + 強大，能戰鬥
  會被「擊散」（損失心靈/run 結束）  - 但不能成長、義體會耗損
- 潛行 + 風險 + 發現            - 是消耗品，不是永久身份
```

逐秒的張力來源：「我還敢不敢再出魂撈一波心靈，還是該縮進義體苟住？」——**玩家自己下的注**，不是被地圖懲罰。義體越擴張越珍貴，賭注越後期越燒腦。

### 柱 3 — 核心資源：心靈（Psyche）

貫穿全局的單一資源，靠**探索**累積（吸靈脈、發現秘密、淨化封印之地、擊散敵靈），用來跨越「附身門檻」——心靈越高，能附身的義體階級越高（雜兵 → 精英/英雄 → 中立遠古守衛 → 終局級）。

**一個資源餵四個 Bartle 象限**：成就者看數字爬升、探索者為它挖地圖、殺手攢夠去輾壓、社交者比誰最快破門檻。這讓「附身」有了重量——是**掙來的**，所以爽。

> ⚠️ 具體門檻數值、階級數量為**開放設計決策**（見 §7），本文件不擅自定死。

### 柱 4 — 召喚重生：召喚 = 準備義體庫存

舊設計的召喚（直接生兵互K）是無聊的根源之一。重定義：

- **召喚 ≠ 直接打架**，而是**事先準備、隨身待命的義體庫存**。
- **初期不可用**：初始狀態是弱小靈體，必須先透過探索強化心靈，才達到附身/召喚義體的條件。
- 危險逼近時「撤回義體」（跳進備好的軀殼）是救命稻草；但躲著就不長心靈、會被更大的黑暗吞掉——逼你再次出魂。

### 柱 5 — 社交地基：Nakama（基礎要有，不偏科）

以 Nakama（開源、Apache-2、可自架於 NAS，零授權費）提供四象限都需要的社交/競技基礎，**接**而非**做**：

| Bartle 型 | Nakama 現成功能 |
|---|---|
| 成就者 | Leaderboards、Tournaments（排行榜/賽季/破紀錄） |
| 社交者 | Friends、Groups、Chat、Parties（真社交層） |
| 探索者 | Storage（build 分享碼）、自訂 RPC |
| 殺手 | Realtime Multiplayer、Matchmaker（真線上 PvP） |
| 全體 | Users（帳號）、Notifications（回流推播）、Purchase Validation |

> Nakama 伺服器端免費，但**整合有真成本**：nakama-unreal 插件接線、每個功能的遊戲內 UI、NAS 自架運維。專案已有 `Backend/Nakama/` scaffold（docker-compose + spirits_match.lua + 整合說明），地基已鋪、尚未接線。

## 3. 探索即附身：雙層地圖（本設計的獨門機制）

探索深度長在唯一的獨門動詞「附身」上，不外接通用道具系統：

```
靈魂層（探索）                    物理層（戰鬥）
──────────────                 ──────────────
未附身 = 幽靈                     附身 = 義體/英雄
- 穿過戰場迷霧（無形）              - 實體、會被打、能打人
- 看得到「靈界」的東西               - 只看得到物理世界
  （隱藏聖壇、遠古守衛、靈脈、封印力量）
- 可附身你發現的東西
```

- **死亡 = 切回探索**，不是結束：英雄陣亡 → 變回自由靈魂 → 飄過全圖（含敵方領地、含迷霧）→ 找下一個值得附身的東西。附身+探索+roguelite 三者焊成一體。
- **附身萬物**：不只自己的兵——敵方單位（策反）、中立遠古守衛（一次性大招）、地形物件（防禦工事）。探索的核心問句從「這地圖有什麼道具」變成「**這地圖有什麼我能附身、附了會怎樣**」。
- **四文明 = 四種靈視**：同一張地圖，東方看靈脈、北歐看盧恩節點、埃及看地下墓室、賽博看資料快取——各解鎖不同隱藏內容。replay ×4，成本低（同圖換覆蓋層）。心靈越高，靈視看得越深。
- **靈界迷霧 = 資訊即資源**：附身一個單位 = 得到它的視野。「我附身哪個」同時是戰鬥決策**和**偵察決策。一個機制餵三象限（探索者操縱資訊、殺手埋伏、成就者算 build）。

## 4. 玩家定位：四象限融合、單一核心循環全吃（不偏科）

巴特爾生態平衡是**多人**現象；本作單機/區網對它免疫——這讓決策變簡單，不是變複雜。四型都服務，但各在對的 scope：

```
成就者（主）  → roguelite 心靈成長、破四文明、難度階         → 核心循環
殺手（情緒）  → 附身英雄 1打5 碾壓 AI 兵潮 + Nakama 線上 PvP  → 逐秒多巴胺
探索者（延壽）→ 附身萬物、四文明靈視、build 組合             → replay 值
社交者（引擎）→ Nakama 排行榜/好友/錦標賽 + 每局產可炫耀片段  → 傳播 = 免費行銷
```

- **社交者是戰略引擎**：每局產出的 build / 翻盤瞬間 / 破紀錄 run → 自動變成 Discord/社群內容，餵專案既有的「內容裂變」機器。這是零預算獨立遊戲唯一買得起的行銷（Vampire Survivors 模式）。
- **不偏科的另一種死法**：四象限全開到滿卻做不完。解法 = **架構一次到位、深度分階段長**（見 §6 路線圖）。

## 5. 重用既有基礎設施（前一輪的工程沒有白做）

pivot 的是 game-design 層；**底層 C++/packaging/backend 幾乎全部保留重用**：

| 既有資產 | 舊角色 | 重新設計中的新角色 |
|---|---|---|
| `ASpiritPawn` / `ASpiritVRPawn` | 靈魂視角 pawn | **魂體探索階段的 pawn（已存在！）** |
| `AUnitBase`（附身 + 輕/重擊） | 場上單位 | **義體戰鬥基底**（附身後的軀殼） |
| `ASpiritsGameMode` / `GameState`（Match FSM） | 兩隊對局狀態機 | **一場 run 的階段推進**（安全→危險→擴張→終局） |
| `AArenaBuilder`（程序化競技場 + FArenaStyle） | Void/Sands 場地 | **可探索地圖 + 危險地帶擴張的承載面** |
| 四文明系統（loadout/tint/pattern） | 四隊召喚差異 | **四種靈視 + 四種義體風格** |
| `ASoulShrine` | 勝負目標建築 | 可保留為靈界地標/附身目標之一 |
| `Backend/Nakama/`（scaffold） | 未接線 LAN 配對 | **柱 5 社交地基**（排行榜/好友/PvP） |
| `build_shipping.ps1` + validators + smoke_preflight | Shipping 打包/驗證鏈 | **原封不動重用**（已驗證：cook/closure/audio gate 全綠） |

> 這是好消息：前一輪把「引擎、打包、測試、後端 scaffold」做到全綠，全部是本設計的地基。重寫的只是玩法。

## 6. 分階段實作路線圖（先讓循環爽，社交/內容才有燃料）

順序鐵律：**核心循環先好玩 → 其他象限才有價值。** 空排行榜、沒人加的好友、沒人分享的戰報，都源自「循環不爽」。

```
P0 設計鎖定（Jun 拍板 §7 開放決策）—— 不動工，先定數值/機制骨架
P1 重用審計 + 魂體探索原型：安全地帶悠閒探索 + 靈界迷霧 + 心靈吸收（先證明「弱靈魂探索」不無聊）
P2 附身門檻 + 義體階級：心靈 gate 附身、雜兵→英雄階級、附身即變身
P3 危險地帶擴張：反向縮圈節奏脊椎 + 魂體被消滅機制 + 終局窒息（含「緊張而不焦慮」護欄）
P4 魂體⇄義體 推幣循環：義體庫存準備、耗損、撤回/再出魂的賭命決策
P5 roguelite 天賦層：每次附身的 build 選擇（探索者/成就者延壽）
P6 四文明靈視：同圖四層隱藏內容 + 四義體風格（replay ×4）
P7 Nakama 社交地基：帳號 + 排行榜 + build 分享碼（day-1 骨架）→ EA 逐步長好友/聊天/錦標賽/線上 PvP
P8 內容/美術/打磨 + 上架（Steamworks、膠囊圖、分級）—— 循環爽了才值得做
```

**每過一 phase 送審計團**（Feynman/Karpathy/Musk），維持方向不歪——沿用專案既有 phase-gate 制度。

## 7. 設計決策 — 已鎖定（P0 於 2026-07-24 由 Jun 整包拍板）

以下 8 項已寫入 `requirements.md` 對應 [DECIDED] 準則；P1+ 可據此開工：

1. **心靈門檻 + 附身階級（3 階）**：Psyche 0–20 雜兵（脆弱暫時）/ 21–50 精英英雄（3 技能能翻盤）/ 51+ 遠古守衛（一次性大招，值 5–10 隻雜兵）。→ Req 1.5
2. **義體耗損模型**：耐久條（非一次性）；耗損滿崩解彈回魂體；主動撤回時凍結保存剩餘耐久。→ Req 3.5
3. **一場 run 長度 + 危險擴張時序**：15–20 分；0–4 安全 / 4–9 危險出現(20%) / 9–15 擴張(60%) / 15+ 終局(90%)。→ Req 2.5
4. **技能數量**：每英雄 3 個（位移/衝刺 + 招牌 AOE + 大招）+ 輕/重普攻，技能綁文明。→ Req 3.6
5. **roguelite 天賦形式**：附身時三選一。→ Req 3.7
6. **RTS 層程度**：RTS-light（召喚=義體庫存輕層）；深度 RTS 明確排除。→ Req 4.4
7. **終局反挫折護欄**：備 1–2 義體、消滅前明確警訊+至少 3 秒逃生窗口、心靈可「淨化」小塊危險區換約 10 秒喘息。**死亡永遠是「玩家自己賭輸」而非「地圖單方面宣判」——終局生死線。** → Req 2.6
8. **四文明靈視 + 可附身特殊目標**：東方靈脈能量流(機動)/北歐盧恩節點(戰力)/埃及地下墓室(隱藏義體+守衛)/賽博資料快取(情報+敵位)；特殊目標涵蓋中立守衛(大招)與地形物件(工事)。→ Req 5.5

## 8. 非目標（維持 scope 紀律）

- **深度 RTS**（經濟/兵種搭配/推線都要有意義）—— 單人開發的 scope 陷阱，明確排除。
- **遊戲內社交基建**（公會系統、房屋建設、遊戲內即時聊天 UI 從零做）—— 用 Nakama 接，不自刻。
- **線上即時 PvP 為 v1 首發必需**—— 列在 Nakama 階段的 EA 逐步長，非首發門檻。
- **社交軸靠「遊戲內社交系統」服務**—— 2026 年社交發生在遊戲外（Discord/Twitch），本作靠「可傳播/可炫耀」服務社交者。

## 9. 誠實的定位總結

這條路把 scope 從「動作 roguelite」拉到「**潛行探索 × 附身 × roguelite 求生**」，比純動作大。換來的是**唯一性**——純動作 roguelite 要跟上千款拼美術手感（現階段都缺）；這條路拼的是沒人有的機制。核心循環一旦爽，社交/內容/美術才有意義；順序反了就是為空排行榜寫程式。
