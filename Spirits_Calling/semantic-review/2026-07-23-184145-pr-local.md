## 刪除 `.gitignore` 使 generated output 進入提交候選

**High / confirmed.** `.gitignore:1-75` 的 Visual Studio、binary、build、Saved、Intermediate 與 DerivedDataCache 規則被整份刪除，且沒有 replacement。`git status --short` 已顯示 `.vs/`、`Binaries/`、`Build/`、`DerivedDataCache/`、`Intermediate/`、`Saved/`、多個 `.sln`/`.slnx` 與本機暫存檔成為 untracked；執行 `git add .`、IDE stage-all 或自動化收集整個工作樹就會把它們納入候選。結果會是巨大且不可重現的提交，也可能夾帶 machine-specific logs、build outputs 或 release evidence。提交前應恢復 base branch 的 `.gitignore`，或加入涵蓋同等 Unreal/VS 產物的替代規則，再逐檔 staging 真正需要的 source、config、tests 與 docs。

## P8 的 action completion 與 WidgetInteraction 只是布林代理

**Medium / confirmed.** task 1.9 要求 oracle 檢查 action completion、hover/click target 與 player transform 穩定（`.kiro/specs/spirits-calling-requirements/tasks.md:89-95`），但 `PropertyP8PlatformActionTests.cpp:96-137` 只建立 `FPlatformActionRouter`、呼叫 `CanDispatch()`，並以 local counter 模擬 handler。註解把 accepted action「代表」adapter completion、把 menu pointer acceptance「代表」`UWidgetInteractionComponent` routing，卻未建立 `ASpiritPawn`、`ASpiritVRPawn`、controller、widget target 或 transform oracle。

任一 handler 不再呼叫 router、pointer 同時送出 possession、或 menu-open movement 改變 actor transform時，P8 仍會全綠。應新增最小 Unreal functional test，經 pawn/controller adapter 發送 movement、menu pointer 與 return/snap actions，斷言實際 handler/target/transform；若暫不建立 functional seam，task 1.9 應改稱只完成 pure routing/scope/snap contract。

## `CoreRuntime` 無法支持 R1.1–R1.12 regression 宣稱

**Medium / confirmed.** task 2.6 已勾選並宣稱補足 spawn、replication、timers、OnRep、combat、restart、HUD routing 與 R1.1–R1.12 end-state（`.kiro/specs/spirits-calling-requirements/tasks.md:146-152`），但 `CoreRuntimeAuthorityAutomationTests.cpp:1-67` 只 include `SpiritsRules.h`，測試 `ResolveDifficultyTuning()`、`ShouldRunAIWaves()` 與 `CanResolveCombat()`。它沒有建立 world、GameMode/GameState、Unit、HUD 或 replicated client；HUD/restart task 2.5 仍標為未完成（`.kiro/specs/spirits-calling-requirements/tasks.md:138-144`）。

Execution Checkpoint 另稱同步 achievement callback 與 `AUnitBase::EndPlay()` 已納入 lifecycle regression（`.kiro/specs/spirits-calling-requirements/tasks.md:11`），但九項 suite 中沒有直接呼叫 `EndPlay()`/`CancelPendingCombat(false)` 的 actor test。應將 2.6 與 checkpoint 改回未完成/人工 code-trace evidence，或補可重跑的 actor/world tests，至少覆蓋 pending heavy/hit-stop teardown、spawn/replication、phase/restart cleanup、OnRep 與 HUD routing。

## Steam pure seam 沒有執行 `USpiritsAchievements` lifecycle

**Medium / confirmed.** task 5.3 已勾選並宣稱覆蓋 Steam client/identity/definitions/write callback、fallback logging、local debug 與 session travel persistence（`.kiro/specs/spirits-calling-requirements/tasks.md:214-220`）。`SteamReadinessAutomationTests.cpp:1-105` 只呼叫 `EvaluateAchievementBackendReadiness()` 並檢查 config IDs；`AchievementPropertyAutomationTests.cpp:1-114` 後續透過 `SpiritsRules::FAchievementEventRouter` 與 fake backend 驗證 event semantics。兩者都沒有 include 或實例化 `USpiritsAchievements`。
